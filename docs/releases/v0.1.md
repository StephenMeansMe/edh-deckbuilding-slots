# Release Plan: v0.1.0

## Overview

v0.1.0 is the first official release of **edh-deckbuilding-slots**. It ships the
complete MVP feature set: a working Linux CLI that lets an EDH deckbuilder
organize a 100-card Commander decklist into named category slots, import and
export plain-text files, persist work across sessions, and trust the app to
maintain structural consistency.

The version number `0.1.0` is already set in `pyproject.toml`.

## US-006 Implementation Plan (TDD)

US-006 covers three distinct consistency constraints enforced through
`handle_card_add` and `handle_card_move` in `commands.py`. Each constraint is
one Red-Green-Refactor cycle with its own commit(s).

### Cycle 1 — Redundant-move no-op (AC 1)

**What it is.**
`card move <card> <category>` when the card is already in that category should
print `'<card>' is already in '<category>'. Nothing to do.` and succeed
(exit code 0). The current code already returns early with a similar message
but omits "Nothing to do." The existing test is named
`test_card_move_returns_error_when_card_already_in_target`, which misnames the
behavior (US-006 explicitly classifies this as a no-op, not an error).

**Red.**
- Rename `test_card_move_returns_error_when_card_already_in_target` →
  `test_card_move_is_noop_when_card_already_in_target`.
- Tighten the assertion to `assert result == "'Sol Ring' is already in 'Ramp'. Nothing to do."`
  (exact string match, not just `"already in" in result`).
- Run `uv run pytest -x` — the test fails because the current message lacks
  "Nothing to do."

**Green.**
In `handle_card_move` (`commands.py:316–317`), update the redundant-move return
to:

```python
return f"'{card}' is already in '{target_cat.name}'. Nothing to do."
```

**Refactor.** None needed.

**Commits.**
```
test: rename and tighten test for card move no-op (US-006 AC 1)
feat: card move no-op prints "Nothing to do." (US-006 AC 1)
```

### Cycle 2 — Singleton non-basic-land rule on `card move` (AC 2–4)

**What it is.**
`card move` currently manipulates `category.cards` directly, bypassing the
singleton exclusivity check that `Decklist.add_card()` enforces for capped
categories. If a duplicate non-basic-land card is somehow present in another
capped category (edge case), `card move` can silently create a second entry.
US-006 requires the move to be rejected with:

```
Error: '<card>' is already in the deck (in '<existing-category>').
```

The check must happen _after_ confirming the card exists (to avoid mutating the
source category on failure) and must exempt basic land cards (consistent with
existing model behavior).

**Red.**
Add to `TestHandleCardMove`:
- `test_card_move_rejects_duplicate_when_card_in_another_capped_category`:
  set up a deck with two capped categories ("Ramp" and "Draw"), add "Sol Ring"
  to "Ramp" directly (bypassing handlers if needed), attempt `card move Sol Ring
  Draw` — assert result starts with `"Error:"` and contains `"already in the
  deck"` and `"Ramp"`.
- `test_card_move_singleton_check_exempts_basic_lands`: add "Forest" (a basic
  land) to Basic Lands and also to Uncategorized (possible after a `card
  remove`), attempt `card move Forest Basic Lands` — assert it succeeds (basic
  lands are exempt from the singleton rule).

Run `uv run pytest -x` — new tests fail.

**Green.**
In `handle_card_move`, after the `is_full` and `allowed_cards` checks and
_before_ the mutation (`source_cat.cards.remove(card)` / `target_cat.cards.append(card)`),
insert a singleton check:

```python
if card not in BASIC_LAND_NAMES:
    for key, cat in session.decklist.categories.items():
        if key == source_key:
            continue
        if cat.capped and card in cat.cards:
            return f"Error: '{card}' is already in the deck (in '{cat.name}')."
```

Import `BASIC_LAND_NAMES` from `models` (it is already available in the file).

**Refactor.** Consider extracting a `_check_singleton` helper if the logic
appears in both `card add` (it is already handled by `add_card()` there) and
`card move`. Keep it in handlers only if duplication is minimal.

**Commits.**
```
test: card move must enforce singleton rule (US-006 AC 2-4)
feat: card move enforces singleton non-basic-land rule (US-006 AC 2-4)
```

### Cycle 3 — Basic-land restriction on `card add` and `card move` (AC 5–7)

**What it is.**
Currently only the inverse is enforced: the `allowed_cards` whitelist on the
Basic Lands category rejects non-basic-land cards. The symmetric constraint —
basic land cards are rejected by any category _other_ than Basic Lands — is
missing. Both `card add` and `card move` must enforce it, printing:

```
Error: Basic lands can only be added to the 'Basic Lands' category.
```

Moving a basic land _into_ Basic Lands is always permitted (AC 7) and is
already handled by the existing `allowed_cards` whitelist path.

Internal operations (`decklist import`, `card remove`) are exempt — they route
basic lands to the correct category by construction.

**Red.**
Add to `TestHandleCardAdd`:
- `test_card_add_rejects_basic_land_to_non_basic_lands_category`: create a
  deck with a "Ramp" category; attempt `card add Ramp Forest` — assert result
  starts with `"Error:"` and mentions "Basic Lands".
- `test_card_add_allows_basic_land_to_basic_lands_category`: attempt `card add
  Basic Lands Forest` — assert success.

Add to `TestHandleCardMove`:
- `test_card_move_rejects_basic_land_to_non_basic_lands_category`: add
  "Forest" to Uncategorized (via direct manipulation); attempt `card move
  Forest Ramp` — assert result starts with `"Error:"` and mentions "Basic
  Lands".
- `test_card_move_allows_basic_land_to_basic_lands_category`: add "Forest" to
  Uncategorized; attempt `card move Forest Basic Lands` — assert success.

Run `uv run pytest -x` — new tests fail.

**Green.**

In `handle_card_add`, after resolving the category and before calling
`add_card()`:

```python
if card in BASIC_LAND_NAMES and category_name != "Basic Lands":
    return "Error: Basic lands can only be added to the 'Basic Lands' category."
```

In `handle_card_move`, after resolving the target category and before the
is-full check:

```python
if card in BASIC_LAND_NAMES and target_cat.name != "Basic Lands":
    return "Error: Basic lands can only be added to the 'Basic Lands' category."
```

Import `BASIC_LAND_NAMES` — already imported at the top of `commands.py`.

**Refactor.** Extract a `_is_basic_land_restriction_error` helper if the guard
appears in more than two places; otherwise inline is fine.

**Scrut functional test.**
Add `tests/functional/09-consistency.md` covering one scenario each for:
- AC 1: `card move` no-op.
- AC 5: `card add` basic land restriction error.
- AC 6: `card move` basic land restriction error.
- AC 2: `card move` singleton enforcement error.

**Commits.**
```
test: card add and card move must reject basic lands outside Basic Lands (US-006 AC 5-7)
feat: enforce basic-land restriction in card add and card move (US-006 AC 5-7)
test: scrut functional tests for US-006 consistency checks
```

## Quality Gates

Run the full suite before tagging. Every command must exit 0.

```bash
uv run ruff check .                                                  # lint
uv run ruff format --check .                                         # format (check only)
uv run ty check                                                      # type check
uv run pytest                                                        # unit + integration
scrut test --work-directory . tests/functional/                      # black-box CLI tests
```

All four commands must pass cleanly (no warnings treated as errors, no skipped
tests with unresolved xfail markers).

### Added

- **US-001** — Create a decklist with named, slotted categories. Fixed

  - `card move` to a card's current category is a silent no-op.

    than Basic Lands.

## Tagging and GitHub Release

Once all quality gates pass and the changelog is committed:

```bash
# Tag the release
git tag -a v0.1.0 -m "Release v0.1.0 — MVP"

# Push the tag
git push origin v0.1.0

# Create the GitHub release
gh release create v0.1.0 \
  --title "v0.1.0 — MVP" \
  --notes-file CHANGELOG.md
```

The GitHub release should be created from `main` after the feature branch is
squash-merged.

## Out of Scope for v0.1.0

Per the ROADMAP, the following are explicitly deferred:

- Partner / Background / Companion fixed slots
- Non-exclusive (multi-category) card placement
- CSV and third-party export formats
- Scryfall integration (legality checks, card lookup)
- Database-backed persistence
- GUI or non-Linux platform support
- `decklist check` command (full consistency scan) — noted in US-006 as future
  work
